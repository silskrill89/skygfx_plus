## 3. Split recipes (per god-file)
- postfx.cpp 7603: keep ONLY the pass orchestration (ColourFilter_switch chain, order, state

## 4. Migration rules (phased, green build each phase)
1. Move code mechanically first (no renames), build, commit-per-phase locally (no push).
2. Then extract shared/ helpers (replace call sites, build).
3. Then register new files in vcxproj (explicit entries) + premake5.lua (glob covers).
4. NEVER-REVERT lists (.serena/memories/swarm-round*+round5*) apply across all moves.
5. postfx.cpp ONE writer at a time; shader files (shaders/ps|vs/*) disjoint → parallel lanes.

## 5. Feature registry pattern (m0163 "one feature at a time" development)
1 feature = 1 cpp + 1 header + 1 INI section + 1 menu tab + 1 segment cost class.
`struct FeatureSeg { const char* name; void (*init)(); void (*frame)(); void (*menu)(); int costClass; }`
registry[] iterated by mode manager + menu. Per-PC-spec segmentation: costClass gates
(default tiers Low/Med/High/Ultra mirroring LibertyRecomp user/config.h enums ESSAO/EDoF...).

  runtime.

## 7. Per-section preset schema (m0022 modes + Grid/ProStreet looks)
INI `[Preset.<name>]` sections: partial config deltas (same mechanism as modeManager profiles).
Composition example: `Grid = PBR pipes + strong grade + ACES tonemap + heavy grain +
  damage-deformation visuals`; `ProStreet = bloom-forward + desat + motion blur + clean AA`.
zzpumas-style enhanced damage = vehicle/damage.cpp visual deformation preset segment.
Mode manager (Modes menu) composes: effective = g_preModeConfig + modeProfile + presetDeltas.

## 8. Forward+ (m0027) target architecture
Holistic forward+ replaces IV/V/RAGE deferred-light-volume mix: O3DE-derived 16px tile cull
(CPU), per-tile 16-index brightest-sorted lists (s5), 256-light atlas (s6/s7), bounded
per-pixel loop in each material shader. Corona/2DFX lights feed ForwardPlus_AddLight.
Project2DFX integration = data feed only (no separate draw path).

## 9. Physics (m0018) — Bullet only, NEVER Euphoria
