## The HARD RULE (2026-11-10, user m0269)

> "we clarifed as a hard rule for this project to always use proper variable names and avoid that
> kind of address calling unless necessary"

Standing interpretation:

- Game/SDK addresses live **only** in one named declaration layer — `src/rw/gta.h` named externs /
  constants (precedent: `d3d9device`, `pDirect`, `CGame__currArea`,
  `DirectionalLightColourForFrame`, offset contracts at `gta.h:391-527`).
- Every call site uses the **name**. Raw hex at a call site is a violation.
- The only exception is a one-off, disassembly-proven constant documented inline as
  "no symbol exists".

Address-hygiene sweep targets are recorded in wave-20 §6 (`main.cpp:1677` begun-camera
`0xC9BCC0`; `rw_fixes.cpp` `0xB4E9E0`; begun-camera sites in `postfx_smaa.cpp:237-241`,
`postfx.cpp:3197`, `pipelinecommon.cpp:1041`; ped-pool `0xB74490`/`0x7C4`/`0x800`;
`0x804EF0` clump-splice).

- **Lanes never build.** One integrated build per gate, run by the orchestrator.
- **Never commit:** `n1`, `qc`, `skygfx_plus_expIV.7z`, `tabshell`/`cloudstore` ps1 files,
  `_backup/`.

- `main.cpp` is single-writer: at most one lane edits it per wave.
- Receipt tokens are byte-stable and **additive only**; log recipes must not be renamed.
- Every new translation unit must be added to `build/skygfx.vcxproj` — premake globs do not
  auto-pick it (W0.2 lesson).
