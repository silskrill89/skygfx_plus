## In one line

The ~3-month black-screen / untextured-world regression is **root-caused**: world geometry was
drawing **UNTEXTURED** — the `TexDefsFindCB` miss path bound a shared 1×1 grey sentinel
(`skygfx_missgrey`, 0x606060) permanently into `material->texture`, so every building/road/prop
rendered grey × ambient. **The pipe is not the defect.** Fix landed in **commit e7bc752
(pushed)**; three one-shot receipts are deployed, **awaiting one user game-run**.

## Verdict — the pipe is not the defect

- Building/vehicle pipe traced end-to-end against AAP (`E:\SDKs\skygfx_original`): matches AAP
  where it matters — hook set, pipe creation, Switch/Xbox cb draw mechanics, CreateShaders,
  Update ambient (plan §2, §4).
- Postfx chain completes every frame: CF-SRC → UpdateFrontBuffer → ColourFilter_Modern →
  Tonemap identGrade → Lens bypass → pf_gate → DrawFinalEffects → "camera raster = final
  displayed surface". Healthy.
- `CustomBuildingPipeline__Update` (`src/render/buildingPipe.cpp:163`): ambient =
  `GetTimecycleAmbientPBR()` = 0.100 per `[PBR-Ambient]` receipt; no zeroing path.
- Zero building-cb receipts in the log are EXPECTED — all are throttled/diagLevel-gated (P4).
- `[PedRS]` first-frame transient (dev src=10 dst=1) self-repairs to ok by frame 9950.

## Root cause — world textures never resolve

| Element | Detail |
|---|---|
| Defect site | `TexDefsFindCB` miss path (`src/texdefs.cpp:699`) — `gameGetTexture` (`0x731720`) parent-walks `dict->parent` |
| Broken link | `dict->parent` is NULL/broken in this ModLoader/ROSA install → full-detail textures looked up while a LOD dict is current FAIL |
| Streaming order | LOD DFFs stream before their parent full-detail TXDs; `TexDefsDictSweep` recovers only if the target dict is ALREADY loaded |
| Poisoning | Miss → shared sentinel **`skygfx_missgrey`**; its name OVERWRITES the requested name (original LOST) → `material->texture` poisoned FOREVER (game never re-requests) → every later frame binds grey |
| Log evidence | Session log (2026-11-16): `[texdefs] miss total=158 distinct=32`, ~3 recovered by cross-dict sweep (`dictfallback`). World-load window (plan §2): `total=32 distinct=32`, ~2 `dictfallback`, 30 → `miss-policy class=world action=sentinel` |
| AAP position | AAP has **no texdefs layer at all** (it assumes the vanilla find works) → install-compatibility defect, NOT an AAP-parity defect |

## Hook verification — RVA theory disproven

- All hook addresses **byte-identical to AAP**: `hookBuildingPipe`
  `src/render/buildingPipe.cpp:4285` = AAP `buildingPipe.cpp:805` (InterceptCall `0x53C15E`,
  InjectHook `0x5D7100`/`0x5D7D90` → CreateCustomObjPipe_PS2, Patch `0x5D7200`).
  `texdefs.cpp:1698` owns the `0x5D7F40` (IsCBPCPipelineAttached) hook with a prologue probe.
- **RVA error of 2026-11-15 DISPROVEN** by correct PE-section mapping: `0x53C15E` = `E8` (CALL),
  `0x5D5B10` = `E9` (JMP) — all hooks valid, identical bytes in both installs.
- **Pipe creation identical**: `CreateCustomObjPipe_PS2` `buildingPipe.cpp:4206/4237` = AAP
  `buildingPipe.cpp:723/754` (RxPipeline + DNInstance_PS2 + reinstance +
  CustomPipeRenderCB_Switch + CreateShaders). CreateShaders ran (ps=55 vs=17 compiled, 0
  failed).
- Switch cb `buildingPipe.cpp:3805` = AAP `:470` + our state prologue/epilogue (additive);
  dispatch Xbox → `_CB_Xbox` (`:2203`).
